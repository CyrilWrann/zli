# Lernprojekt-GitHub
 
Dieses Repository ist mein Lernprojekt für GitHub.
Ich übe hier, wie man im Team mit GitHub arbeitet.
 
## Ziel des Projekts
 
Ich lerne in diesem Projekt:
 
- ein Repository erstellen
- ein Project-Board (Kanban) benutzen
- Issues schreiben und Labels setzen
- einen Milestone anlegen
- Aufgaben verteilen und abschliessen
- mit anderen zusammenarbeiten (Feedback und Kommentare)

## Das Project-Board
 
Das Board heisst **Lernprojekt-Board**. Es hat vier Spalten:
 
1. **To Do**: Das muss noch gemacht werden.
2. **In Progress**: Daran arbeite ich gerade.
3. **Review**: Das muss noch geprüft werden.
4. **Done**: Das ist fertig.
## Die Issues
 
| Nr. | Titel | Label |
|---|---|---|
| 1 | Projektstruktur definieren | Enhancement |
| 2 | README-Datei vervollständigen | Documentation |
| 3 | Feedbackprozess definieren | Process |
 
Alle drei Issues gehören zum Milestone **Projektsetup**.
 
## Milestone: Projektsetup
 
Alle Vorbereitungen für den Projektstart werden abgeschlossen.
Der Milestone ist erledigt, wenn alle drei Issues geschlossen sind.
 
## Projektstruktur
 
```
Lernprojekt-GitHub/
├── README.md      Beschreibung des Projekts
└── (weitere Ordner und Dateien folgen in Issue 1)
```
 
## So arbeite ich mit dem Board
 
1. Ich nehme ein Issue aus **To Do**.
2. Ich ziehe die Karte nach **In Progress** und starte.
3. Ich schreibe einen Kommentar, wenn es Fortschritt gibt.
4. Ich ziehe die Karte nach **Review**, wenn ich fertig bin.
5. Nach der Prüfung ziehe ich die Karte nach **Done**.
6. Ich schliesse das Issue mit einem kurzen Kommentar.
## Feedbackprozess
 
So gebe ich Feedback und prüfe Arbeit:
 
1. Wer fertig ist, schreibt im Issue einen Kommentar: "Bitte prüfen."
2. Eine zweite Person schaut sich die Arbeit an.
3. Die Person schreibt ihre Rückmeldung als Kommentar.
   - Was ist gut?
   - Was kann besser werden?
4. Wenn etwas angepasst werden muss, wird es verbessert.
5. Danach wird das Issue geschlossen.
Regeln für gutes Feedback:
 
- freundlich und klar schreiben
- kurze Sätze benutzen
- Vorschläge machen, nicht nur Kritik
## Zugriff für Coaches
